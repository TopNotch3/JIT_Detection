# UX Principles

## 1. Explain the risk

A risk score without evidence is not enough.

## 2. Reduce review effort

The interface should help users decide where to look first.

## 3. Preserve context

A developer should be able to move from:
repository → commit → file → code region → explanation.

## 4. Show uncertainty

Use calibrated confidence and explicit limitations.

## 5. Do not create false authority

Avoid language such as:
- "This code definitely contains a bug."
- "The AI knows this will fail."

Prefer:
- "Predicted defect risk"
- "Model evidence"
- "Confidence"
- "Review recommended"

## 6. Progressive disclosure

Show high-level risk first and technical details on demand.

## 7. Fast path

A user should understand the most important risk information within seconds.

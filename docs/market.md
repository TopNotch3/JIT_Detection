# Market and Adoption Analysis

## Status

**TBD / research required**

The original course proposal defines a developer-facing JIT-DP demonstrator but does not provide validated market-size, pricing, customer-count or revenue data.

Therefore this file intentionally does not invent TAM/SAM/SOM numbers.

## Potential product category

The system can be positioned conceptually as:
- software engineering intelligence;
- automated code-risk analysis;
- AI-assisted code review;
- defect prediction.

The final commercial positioning requires research beyond the course proposal.

## Research questions

1. Which organizations have a measurable need for JIT defect prediction?
2. Which existing tools already provide commit risk or code-risk analysis?
3. What data/privacy restrictions affect repository analysis?
4. What level of false positives is acceptable to developers?
5. How much review time could a reliable system save?
6. Would teams trust a risk score without an explanation?
7. What deployment model is preferred: cloud, self-hosted or hybrid?
8. What integrations are essential?

## Evidence requirements

Any market claim added later must include:
- source;
- date;
- geography;
- population/sample;
- methodology where available.

## Commercial hypotheses

These are hypotheses, not established facts:

- Repository-level risk visibility may be more useful than isolated model scores.
- Explanations may improve developer trust.
- Enterprise environments may require private deployment.
- Integration with existing Git workflows may reduce adoption friction.

Each hypothesis should be validated before appearing in an investor-facing claim.

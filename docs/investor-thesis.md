# Investor / CEO Review Thesis

## Important disclaimer

This is an evaluation framework. It does not claim that the project is currently investable.

## 1. Problem

Software teams need to identify risky changes before defects reach production.

## 2. Existing limitation

The proposal identifies shortcut-learning concerns in existing JIT-DP approaches under counterfactual evaluation.

## 3. Proposed differentiation

The project combines:
- structural code representation through diff graphs;
- counterfactual-contrastive training.

## 4. Potential moat hypotheses

These are hypotheses requiring validation:

- specialized structural representations;
- proprietary/curated counterfactual generation recipes;
- high-quality labeled commit datasets;
- evaluation methodology focused on shortcut robustness;
- integration into developer workflows.

## 5. Investor questions

A skeptical investor/CEO should ask:

1. Why is the problem expensive?
2. Who will pay?
3. Why are existing code-analysis tools insufficient?
4. Is the model actually better?
5. Does it reduce false positives?
6. Does it generalize across repositories?
7. What is the deployment/privacy model?
8. What prevents a large platform from copying the feature?
9. What proprietary data accumulates?
10. What evidence shows developers trust the output?
11. What is the measurable ROI?
12. What is the path from research prototype to product?

## 6. Evidence required before an investment claim

- benchmark results;
- ablation results;
- counterfactual robustness results;
- user feedback;
- measured workflow value;
- deployment feasibility;
- market research.

## 7. CEO-level pitch

The strongest future pitch should follow:

Problem → Evidence → Existing failure → Technical insight → Product → Measured improvement → User value → Defensibility → Business model → Roadmap.

Avoid leading with model architecture.
